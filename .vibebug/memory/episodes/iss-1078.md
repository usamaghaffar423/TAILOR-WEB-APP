# Notes typed on New Order now print on the karigar bill and survive into the order record.

Root cause: KarigarBillModal rendered no notes section at all, so nothing was ever printed on the karigar bill. On create the order snapshot's notes came only from the just-upserted measurement row, and NewOrder's async customer preload (selectCustomer -> customersApi.show().then) called setNotes(latestMeasurement.notes || '') when the response resolved, overwriting any note typed before or while that request was in flight — production orders ORD-0096..ORD-0101 had empty notes in BOTH the measurement row and measurement_snapshot while their measurement fields saved fine, so the note was gone before the order was stored and the detail page showed a dash.

Fix/outcome: NewOrder keeps notes the shop owner already typed (notesTouchedRef guard in the textarea onChange, preload only fills an untouched box) and sends measurement_notes with ordersApi.store; OrderController::store snapshots that note with the measurement row as fallback, validated by StoreOrderRequest (max:1000); KarigarBillModal prints a notes section from measurement_snapshot.notes. CustomerBillModal and OrderCardModal already rendered the snapshot notes.

Changed: frontend/src/pages/NewOrder.tsx, frontend/src/components/orders/KarigarBillModal.tsx, frontend/src/api/orders.ts, backend/app/Http/Controllers/Api/OrderController.php, backend/app/Http/Requests/StoreOrderRequest.php

Verified: npm run build, npm run lint, php -l on both backend files, deployed Vercel NewOrder chunk contains measurement_notes and the karigar chunk the new notes render, deploy run 36696670521 success with production files containing the change
