# Style Customization dropdowns now offer a Delete option; choosing it clears the field so the customization is never stored and never printed on the karigar bill.

Root cause: The brand Dropdown component has no way back to 'Select…' once a value is picked, so a style value could never be unset: NewOrder/EditOrderModal/NewSalePage passed STYLE_FIELD_OPTIONS straight through and saved whatever was picked, and KarigarBillModal prints a row for every truthy style value.

Fix/outcome: Added STYLE_DELETE_OPTION plus styleFieldOptions()/styleSelectionValue() in styleFields.ts and used them at all three style-field render sites: Delete stores '' , all three forms send only non-empty style values, OrderController replaces style wholesale, and KarigarBillModal filters on truthy values, so a deleted customization is absent from the bill while real selections still print.

Changed: frontend/src/lib/styleFields.ts, frontend/src/pages/NewOrder.tsx, frontend/src/components/orders/EditOrderModal.tsx, frontend/src/features/sales/pages/NewSalePage.tsx

Verified: npm run build, npm run lint, node assertion harness for styleFieldOptions/styleSelectionValue
