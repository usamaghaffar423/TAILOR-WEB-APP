# An order can be moved to another customer, splitting orders that shared one record.

Root cause: CustomerController::store used to merge customers on phone, so a second person sharing a number inherited the first person's record and both orders landed under the same customers.name — the Orders group rendered one name for two people. main already always creates a new record, but nothing could move an order back off the merged customer: UpdateOrderRequest had no customer_id rule and the edit modal had no customer field, so the pair could never be split.

Fix/outcome: PUT /orders/{id} accepts an optional customer_id (validated against customers), applied after the measurement push-back so profile writes still land on the customer the order was filed under; the mirrored sale row and customer caches follow the move. EditOrderModal gained a customer search (name / phone / customer ID) that stages the move and only sends customer_id when it changed, with a toast confirming the move.

Changed: backend/app/Http/Controllers/Api/OrderController.php, backend/app/Http/Requests/UpdateOrderRequest.php, frontend/src/api/orders.ts, frontend/src/components/orders/EditOrderModal.tsx
